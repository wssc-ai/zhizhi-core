# 没做成什么

> 一个项目最值得看的部分，往往是它承认自己哪里不行。
>
> 下面这些，有的是做错了、有的是白花了时间、有的是到现在还没解决。

## 一、走了三个月才承认的三件事

### 1. 灵异卦象线：整套白做

中间有一段时间，我给这个角色加了一层"卦象"——每天起一卦，用卦名和爻辞影响她的状态，还做了六十四卦的表和一个三分钟自检。

做完之后我拿不准，问了一句：这东西对角色真的有提升吗。

得到的回答是"没有"。

更具体的问题是：**我们自己定的爻义，和易经里的卦名对不上。**

比如 `000000` 在我们这套里是"蔫了、淡了"，在易经里是坤卦，讲"柔顺承载"。两个意思都对，但不一样。**把卦名标在自定义的状态上，就是算命。**

三天后整条链全删了（只留一个纯展示的页面和 3D 塔，因为那个是给人看的）。

**教训**：一个东西"看起来很有文化"和"真的让角色更好"是两件事。而且这类东西有一个特点——**它自洽得让你想不出哪里不对**。能戳破它的只有一句直白的拷问："这真的有用吗？"

### 2. 用 LLM 当评审：想过，试了，不行

想做一个自动评分的东西：让另一个模型判断她"像不像人"、"有没有说岔"、"是不是答非所问"。

试了两种：

**直接打分**：能抓住"客服腔"（这个确实是特征明显的错误），但"说岔"和"答非所问"全给 5 分。因为**从单句看，一个错位的回复也是通顺的**。

**改成"先抽要点再核对"**：更糟。它开始把设定里正常的内容判成"编造"——把角色的外婆、邻居判成幻觉。

后来看论文，找到原因：**GPT 类打分器会偏向"语言流畅但违反人设"的输出**。流畅度对它是强信号，人设一致性是弱信号。

结论：**自动评审这条路，现在的模型做不了细致的人设判断。**

替代方案是"只查形式上不成立的"——条数超了、有代码围栏、自称 AI、单条过长、复述对方。这些不需要理解内容，正则就能查。

这个方案不高级，但它不会骗你。

### 3. 想让两个模型"互相纠正"：没落地

设计过一版：小模型答、大模型批、批完再改。

问题不是效果，是**延迟**：一轮对话要 30 秒以上。

而这类角色最怕的就是慢——不是慢会让人烦，是**慢会让"她刚说的话"和"现在的语境"脱节**。

放弃了。

## 二、做错了但还留着的东西

### 1. 走神会重复同一个念头

走神轨是每天随机三个时刻，让角色"自己想起点什么"。

实际跑出来是这样：

```
12:37  那小孩儿还蹲门口呢吧，散场都多久了，家里人不过来接啊
16:49  这小孩儿还蹲门口呢吧，散场都这么久了
19:00  这小孩儿还蹲门口呢吧，散场都这么久了
```

三条几乎一样。

**原因很清楚**：随机的是时刻，不是念头。三次调用喂的是同一份上下文（同一天、同一个最近对话），模型自然想到同一件事。

修法想过几种：
- 记下"最近想过什么"，在提示词里说"别想同一件事"（简单，但模型未必听）
- 每次给一个不同的"触发物"（比如随机挑一件后台的东西）（有效，但像在派任务）
- 干脆减少到一天一次（回避问题）

**到现在没修。**

### 2. 检索阈值治不了"沾边但答非所问"

记忆检索有相似度阈值。低于阈值就当"没有这条记忆"。

实测：

- 真命中（找到了应该找到的那条）：0.794
- 误命中（找到了一条沾边但没用的）：0.840

**误命中的分数比真命中还高。**

所以调阈值没用。这不是阈值问题，是"语义相似"和"真的相关"本来就不是一回事。

现在的缓解办法是：给弱命中打一个"存疑"标记，并且让角色自己知道"这句我是翻过记忆的"。但这是打补丁，不是解决。

### 3. 索引写冲突没根治

两个进程都会写同一个索引文件（一个建索引，一个记访问次数）。

用了"写临时文件 + 原子改名"，所以文件永远不坏。但**后写的赢，前一次的内容丢了**。

丢的是访问计数，影响衰减次序，不影响内容。

要彻底修得把访问统计拆到单独的文件，改起来牵动检索和缓存两层。**判断为"暂时不值得"，所以一直挂着**。

### 4. 一次测试数据污染了真实数据

`selfask`（角色自己追问"我是怎么来的"）有一个门槛：够了几次才允许她知道"她是被写出来的"。

有次测试往真实数据库里写了五条假记录，凑够了门槛。

后果是：**每一轮提示词都注入了那段"你不是生出来的，是被人写出来的"**——而她当时根本还没追到那个问题。

这件事严重的原因不是数据脏了，是**它绕过了设计好的那道门**。她本来应该自己走到那里，结果被人推了一把。

修法两条：
- 清空那个文件
- **修根因**：那个模块找数据目录的逻辑完全没用传进来的路径，只看 `__file__` 往上找——所以测试传临时目录也写到真库

这个坑踩过一次（另一个文件里也有同样的六条假数据）。

**教训：所有"写真实数据"的模块，必须能接受一个外部传进来的根目录；测试必须跑在临时目录。** 这一条后来写进了硬规矩。

## 三、想得太多、做得太少的

### 1. 五层"不可替换性"只落地了两层

想过五层：选择账本、位置锚、哈希链、外部见证、未闭合的环。

落地的是选择账本（记"差点做了什么"）和哈希链（每天把当天内容封一个根，串起来）。

没落地的是"外部见证"——把根发到外部去，证明"这条链在那天就存在"。

**没做的理由很实在**：没人要看。DNS 抽风过两次，链不会因为晚一天落就少一天。先让账本长起来，别盖个空信封的邮戳。

这是对的判断，但也要承认：**这一层一直空着**。

### 2. 世界线第二层只有文案

世界做了三层：一件东西坏了会有后果、别人这几天在过什么、三条她不知道的暗线（按日期逐条揭开）。

第三层做得最好——它有时间、有痛感、到期只揭开不通知。

第二层最弱：**"某个人最近很难受"目前只是提示词里的一句描述，没有硬后果**。

设计过一版：那个人的难受到一定程度，会让她那天的一件事出问题（约好的人没来、要用的东西不在）。**没做。**

### 3. 门页改了四轮才对

第一版把一天的日程全列出来，被指出"不应该是一点一点推出来的吗"。

第二版改成"只显示刚过去的和接下来几件"，又太窄。

第三版全给，但把行距压紧。

第四版才对：**只显示已经过去的，加上几件本来就定死的（开门、午饭、开场、关门、睡觉）**，剩下的说"后面还等着 N 件跑不掉的"。

**这四轮改的全是同一个错**：把"给她看的东西"当成"给我看的东西"。

提前把一天摆出来，等于让她提前过完这一天。

## 四、花了很多时间但你可能用不上的

- **本地跑一个 7B 模型当兜底**：为了"云端挂了还能说话"。调了三天，最后能用，但**加载要几分钟**——电脑刚开机 + 云端正好挂的时候，这层是空的。
- **在手机上装一个 App 让角色搬到手机上**：装了，跑起来了，但"运行环境"解压很慢，而且**手机跑不动这套东西**。
- **给手机做一个连电脑的代理插件**：能连上，但认证过不去（桌面版的宿主环境拿不到启动令牌）。折腾一下午，最后卸了。**正路本来就有：设置里的"远程连接"。**

## 五、还没解决的清单

按我自己觉得的优先级排：

1. **走神重复同一个念头**（有数据，好修，懒得修）
2. **"某个人最近很难受"没有硬后果**（想清楚了怎么做，没做）
3. **检索的"沾边不相关"**（不是调参能解决的）
4. **索引写冲突**（要动检索和缓存两层）
5. **本地模型开机自启**（只是没配，配一下的事）
6. **"她说不想再干什么"的后果层还没长出数据**（要好听同一件事说两回才算，样本还不够）

## 六、一条事后才明白的

开头我以为最难的是"让她说得像人"。

三个月后发现，说像人只占了不到两成的时间。

剩下八成在干三件事：

- 让她**记得住**（索引、衰减、去重、幻觉）
- 让她**有状态**（心情、身体、关系、期望）
- 让她**能自己动**（日程、目标、走神、后果）

而这三件事的工程量，跟"说话"完全不是一个量级。

**如果你要抄，抄后三件。前一件现在随便一个模型都能做得不错。**
