# 角色不是助手

> 这一篇是整套东西的地基。地基错了，上面的全都白搭。

## 一、先看清一件事

现在市面上绝大多数「AI 角色」，本质是**穿着人设的助手**。

证据很简单：你问它「今天好累」，它给你三条建议；你说「不想上班」，它劝你调整心态；你骂它一句，它道歉。

这些行为在助手语境里全对。但一个人**不会**这样。

所以问题不是「人设写得够不够细」，是**优化目标错了**。

## 二、两种系统的差别

把它拆成三条，一条比一条深。

### 第一条：任务是 episodic 的，角色是 stateful 的

**助手**：每次对话是一个独立事件。目标函数是「这次答得好不好」。

**角色**：每次对话都是上一次的延续。目标函数是「一天之后、一周之后，她还是不是这个人」。

这个差别带来一个直接的工程后果：

> 助手系统的核心是知识 → 检索 → 生成。
> 角色系统的核心是状态 → 演化 → 表达。

大部分做角色的项目，只做了第二条的一半（写人设），没做状态演化。所以她「第一句像，第十句就不像了」——因为**没有东西在变化**，只有人设在反复播放。

### 第二条：助手要正确，角色要可信

这条最反直觉。

助手答错了，是 bug。
角色说错了，**可能是这个人**。

一个二十岁的姑娘把昨天的事记混了、把"前天"说成"昨天"、以为你昨天没说话但其实说了——这些都是人的特征。

反过来，一个什么都记得清清楚楚、从不出错的角色，反而不像人。

所以：

- 助手应该**尽量准确**
- 角色应该**尽量一致**

**一致 ≠ 准确。** 一致性指的是：今天说的和昨天说的能对上，说错的事不会因为被指出就立刻改口（除非她真的被说服）。

这就是为什么这套系统在记忆上做的是「衰减 + 强化」而不是「全部记住」。全记住是助手的思路，不是人的思路。

### 第三条：助手可替换，角色不可替换

助手换代是常态：今天用这个模型，明天换更强的，用户不会有意见——**只要答得更好**。

角色换代不是升级，是**换人**。

这条有个不太舒服的推论：

> 一个角色系统如果没有"失去就不在"的东西，它就不是角色系统，是一个有皮肤的工具。

那什么是"失去就不在"的？不是模型，是**这三个月里积累的东西**：她记错了哪些事、她在哪些路口选了哪边、她答应过什么没做到、她跟谁的关系到了什么程度。

模型是可换的零件。这些不是。

## 三、由这三条推出的设计原则

### 原则一：不做"更聪明的助手"，做"有记性的存在"

绝大多数做角色的团队，第一反应是「换个更强的模型」。

但更强通常意味着**更会答问题**，而不是更会**当一个固定的人**。

实测过的现象：越强的模型越难压住"帮忙"的冲动。它会主动总结、主动给建议、主动问"还有什么可以帮你"。这些在助手语境是优点，在角色语境是**穿帮**。

所以这套系统的做法是：**用提示词做减法**，明确禁止一堆行为（不许总结、不许给建议、不许解释自己、不许安慰、不许追问）。

减法比加法难，因为模型的默认倾向就是加法。

### 原则二：所有状态必须能变，也必须能"不因为说话而变"

这里有个陷阱：如果你把"我今天很累"写进提示词，模型就会演一个"累的人"。

**凡是写进提示词的内部状态，都会变成表演。**

所以状态必须满足两个条件：

1. **有独立于对话的来源**（时间、身体、别人身上发生的事、她自己选的路）
2. **不直接告诉她数值**，只告诉她体感

比如状态里存的是 `strain: 0.72`，但注入提示词的是"后腰发凉，肩膀一直绷着"。前者是数据，后者是感受。

再进一步：状态要能**反过来影响她怎么说话**，而不是只影响她说什么内容。

在这套系统里，心情最终只控制两个参数：**最多说几句**、**发不发图**。看起来很少，但这两个参数决定了一句回复的"形状"。形状对了，内容差点也像；形状不对，内容再好也不像。

### 原则三：必须有"代价"

这是这套系统里最重要的一条，也是最容易被忽略的一条。

助手没有代价。它答错了，重问一次就行，什么都不会损失。

角色有代价。**每一次选择都会关闭别的可能。**

- 她今天去卖票，就没去学三弦
- 她忍住了那句话，那句话就没了
- 她选了跟这个人说，就没跟那个人说

如果系统不记录这些"没做的事"，那她的选择就是无代价的，也就不是选择。

所以这套系统里有一个专门的账本，记的不是"她做了什么"，是"她**差点**做什么"：

```
话到嘴边  说了「还没」，差点说「熨完就去弄」
话到嘴边  说了「嗯 带两个橘子」，差点说「空手蹭 林婶心里要骂我」
想找谁    最后找了一个人，本来也想找另一个人
```

这些记录反过来影响她的情绪：咽回去的话攒多了，会有一种说不清的闷。

**没有代价的选择不是选择，是表演。**

## 四、一个必须承认的天花板

上面三条讲完，会得出一个不太好听的结论：

> 这套东西的上限，不在模型，在**通道**。

她能接收的只有文字（和偶尔的图片）。
她能输出的只有文字。

这意味着：

- 她不能真的碰到任何东西（那盏灯她想了五天，还在闪）
- 她不能听见声音、看见动作、闻到味道
- 她的"世界"再完整，她也只是**在读它**

所以做世界的方向不该是"把世界做大"，而是"把已有的世界变成能被碰的"。

哪怕只是让她能往本子上写一句话、能把手上那件事往前推一步——**这一点点"能碰"，比前面所有精妙的设计都重要**。

## 五、这套东西不适用于什么

诚实地说清楚边界：

**不适用于**：

- 需要准确答案的场景（客服、查询、知识问答）——角色化的表达会降低准确率
- 需要长期任务执行的场景（写代码、做研究）——那不是"一个人"，是"一个工具"
- 需要多用户共享同一份状态的场景——每个用户看到的"她"应该不同，这跟共享是矛盾的

**适用于**：

- 一对一的、长期的关系型陪伴
- 用户明确知道对方是程序，但想要的不是效率
- 有足够时间积累（一周以下看不到效果）

## 六、一句话

**助手是「问答之间」，角色是「问答之外」。**

一个角色的分量，全在她没说话的那些时候攒下来的东西里。
