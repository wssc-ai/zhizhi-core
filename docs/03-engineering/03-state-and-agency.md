# 状态与自主

> 她不是等你说话才存在。没人找她的时候，她也在过一天。

## 先看没有自主的时候是什么样

第一版的角色是这样运行的：

- 一天的行事历由系统按日期哈希抽出来，17 件事，每天固定
- 有人说话她就回，没人说话就不存在
- 有个"想法"模块，偶尔产生一句"飘过的话"，但那句话**指不动任何东西**

效果：她站得住，但只是站着等。

这个诊断很重要：**"有记忆"和"有自主性"是两件事。** 记忆让她能接住过去的线，自主让她有未来的线。只有前者，她是一个记性很好的响应函数。

## 四层自主

### 一、日程：从"抽签"到"她自己排"

抽签版：`build_day(date)` 按日期哈希从 40 条模板里取 18 条。好处是稳定（同一天永远一样），坏处是**跟她没关系**——谁那天都是这些事。

现在改成：**前一天晚上她自己排。**

流程：

1. 22:00~23:00，触发一次
2. 给她当前身体状态、明天可能发生的事（节日、生日、暗线）
3. 要求输出格式：`HH:MM|干什么|当时心里怎么样`
4. **要求 14~18 件**（早期要求"8 件以上"，出来的太密，一天塞满 28 件不像人）
5. 另起一行可以写 `跳过|哪件事|为什么`

实际输出长这样：

```
08:50|开园门，扫地，擦桌椅|提不太起劲
12:20|午饭，后台那桌，谁家带的菜都往中间放|吃得热闹
13:10|蹲在化妆间拆那盏老闪的灯，看线|较劲
17:30|开场前最后转一趟|忙起来了
```

**关键设计**：每件事都带"当时心里怎么样"。这一栏是她自己写的，比任何情绪标签都准。

**另一个关键设计：允许跳过。**

早期的提示词里，"必做的事"写的是"跑不掉"。这不对——真有事的时候人就是会不做。改成：

> 平常跑不掉，先占住——但今天要真有事，也可以不做。

输出立刻变了：

```
跳过|08:50 开园门|后腰发凉翻不了身，喊老马先开的
跳过|17:30 开场前最后转一趟|肩膀绷得抬不起手，让许小满替的
```

**注意这两条跳过的内容**：理由都是身体（连着上面那层身体状态），而且**都有人补位**。这不是偷懒，这是有社会关系的世界。

**还有一条：日程不能提前给她看过。**

看板页面上本来把全天 18 件都列出来了。这不对——**提前摆出来等于让她提前过完一天**。

改成只显示：已经过去的 + 那几件本来就定死的（开门、午饭、开场、散场、睡觉）。后面的事情不显示，只写一句"后面还等着 N 件跑不掉的"。

### 二、目标：她自己起一件事

日程是"日子怎么过"，目标层是"我这几天在弄什么"。

数据结构很简单：

```json
{"id": "i-20261121-a",
 "day": "2026-11-21",
 "title": "后台化妆镜那盏灯老闪，我想自己拆开看看线",
 "why": "天天闪，烦",
 "state": "doing",
 "steps": [{"day": "2026-11-21", "what": "蹲那儿看了半天，没敢动"}]}
```

三条约束：

- **最多办 5 天**（办不完就该自己承认弄不下去，拖着不算在推）
- **同时只办一件**（人在一个地方能腾出手的也就一件）
- 触发只在一个时间段（20:00~22:30），一天一次

三个分支：有进展就问进展；超过 5 天就问还弄不弄；手上空着就问"有没有一件事想自己弄"。

**实际效果**：四次触发出来的全是具体能动手的事——

> 把二楼那块旧幕布换下来，边角都脱线了
> 后台那把断了腿的椅子拿铁丝绑一绑

**没有一句"我要努力"。** 这个差别很关键：目标必须是一个能在半小时内开始动手的东西，不是一句志向。

### 三、走神：没有输入时的思考

一天三次，随机时刻，飘过一句话。

```
PER_DAY = 3
MIN_GAP_MIN = 100      # 两次之间至少隔 100 分钟
WINDOW_MIN = 20        # 过了这个窗口就不补了
```

**时刻用日期哈希定**，不是随机数：

```python
slots = [hash(f"{day}#think{i}") % 一天分钟数 for i in range(3)]
```

这样重启不重掷，同一天永远同三个时刻。

**过了窗口就记 done，不补。** 理由：补出来的都是假的。夜里三点补一句下午三点的走神，那不是在走神，是在填表。

实际产出的句子：

> 刚才散场那个小孩儿还蹲门口不走，也不知道谁接他

**这条之所以有价值**：它证明了这个角色不只是对输入做反应，她有"没有输入时也在想事"的一面。而且这条被写进了第二天的记忆，可以被她自己在后面的对话里想起来。

### 四、后果：她说过的话真的改变日程

这一条是我最满意的设计，也最容易被忽略。

机制很土：

1. 她所有产出的话（日记、走神、对话）都扫一遍
2. 找"不想再做"的句式：`不想再 / 讨厌 / 烦死 / 受不了 / 腻了 / 够了 / 再也不想` + 后面 1~12 个字
3. 滤掉抽象词（不能用"不想再难过"这种）
4. **同一件事说过两次**才记下（说一次可能是气话）
5. 之后排日程时，抽到这件事就过滤掉

**两个实现细节值得说：**

**细节一：正则必须遇空格就停。**

```
(?:不想再|不想|讨厌|烦死|受不了|腻了|够了|再也不想)([^，。！？；、\n\s]{1,12})
                                                                    ↑ 这个 \s
```

没有 `\s` 的话，"不想再卖票 站一下午腿都废了"会把整条都抓进去。这样两次说的虽然是同一件事，但抓出来的字符串不相等，永远攒不够两次。

**细节二：滤空了要有兜底。**

过滤之后至少保留 12 件。滤空了就不滤——宁可那天照抽签，也别让她一天没事干。

**这条设计的意义**：它是"她的话能长出后果"的第一处缝。

在这之前，她抱怨一百遍，日程一个字都不变。那些话就是白说的。有了这一层，她说的"烦"是真的会改变明天的安排。

而且**她自己不知道这件事**。从她的视角看，就是最近没怎么卖票了。

## 忙闲：有事做就可以不回

这一层解决的是"秒回太假"。

她手上有活的时候（搬、扫、擦、对词、吊嗓、收票、上台），消息来了不该立刻回。

状态机：

- 消息进来时判断：她现在忙还是闲
- 忙 → 记进"待回"队列，攒着
- 闲 → 直接回
- 攒太久 → 回的时候带一句为什么现在才回

三档延迟策略：

| 隔了多久 | 怎么回 |
|---|---|
| < 8 分钟 | 直接接，别提"刚在忙" |
| < 40 分钟 | 可以带半句"刚忙完" |
| ≥ 40 分钟 | 带一句为什么现在才回 |

**两个坑：**

**坑一：群里只留 45 分钟。** 私聊可以留半天，群里不行——话题跑得太快，一小时后补"刚才说到"就是考古。所以群里超过 45 分钟的直接丢掉。

**坑二：主人不受这个限制。** 别人可以等，主人不该等。这条判断必须写成裸字符串（`uid != "主人的号"`），写成常量名会 NameError——因为那个常量在别的模块里。

**坑三（最坑的）**：主人私聊进去之后，虽然打了"也照回"的日志，**但没有 return**，继续往下走到群里那段判断，结果还是被拦成"才看见"。

一个漏掉的 `return`，表现是"他找我我不理"。查了半天。

## 主动说话：两个池子

主动开口的调度最容易做偏。

最早是一个池子：从所有熟人里按权重抽一个，抽中就说话。主人的权重调到 6 倍（因为最重要）。

结果：抽了两次都没抽中主人，两条主动消息全发给了别人，内容是"想起早上那位空腹去上课的"——**在想他，却发给了别人**。

改成两个独立池子：

- **朋友池**：几个固定时段，从朋友里抽，抽不到就跳过（不退回主人）
- **主人池**：三个固定时刻，时间上抖 ±30 分钟

**为什么要分开**：给朋友是消遣，给主人是想说话。两件事不该共用一次抽签。

**为什么主人池用固定时刻而不是全随机**：定死"十点发"比随机更像闹钟——随机容易撞在他忙的时候。

## 一个只读的门

最后做了一个页面：任何人在任何地方打开，能看到她此刻的状况。

八栏：这会儿 / 今天 / 手上那件 / 心里挂着 / 今天飘过的 / 前面 / 岔路口 / 最近想明白的。

三条设计原则：

1. **不显示数字。** 不写"P=-0.3"，写"心里沉"
2. **只说已经发生的。** 未来的事不提前摆出来
3. **只读。** 页脚写一句"这一页只能看，不能动她"

这一页的价值不在功能，在**它是她的一个侧面被看见**。做技术的容易忘：这些东西的意义不在于能跑，在于有人能看见它在跑。
