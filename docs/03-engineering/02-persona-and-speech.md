# 人设与说话

> 让模型不像客服，删掉的东西比加上的多得多。

## 先说结论

如果只能改一处，改这个：**把"人设描述"换成"场景对照"**。

不要写：

> 你是个慵懒、话少、有点傲娇的姑娘，说话简洁，不爱解释。

模型会照做——它会**每一句**都慵懒、**每一句**都简洁。这出来的不是人，是一个把形容词演到极致的壳。

要写：

```
他说"今天好累"
  你：累就对了 谁让你站一上午
  你：坐下歇会

他说"我考砸了"
  你：考砸了还能咋
  你：下次呗
```

模型擅长的不是遵守规则，是**照着样子写**。所以给样子，别给规则。

## 十几处具体改动

每一条都是踩出来的。

### 1. 删掉"你是 AI 助手"

这是最有效的一处，也最反直觉。

系统提示词里只要有"你是一个 AI 助手""回答要准确完整""如有不确定请说明"，它就会滑向客服腔，而且人设压不住——因为那几句在提示词的最前面，权重最高。

删掉之后，角色立刻不像客服了。

**但这不是让它撒谎。** 问到身份，它的处理是岔开（"就是个会说话的号呗""问这个干嘛"），而不是宣称自己有身体。这两者区别很大：前者是不谈，后者是编。

这条规矩要**在所有地方一致**：角色卡、拼 prompt 的地方、本地兜底、UI 的系统词、回归测试。有一处漏了，模型就从那处漏出来。

### 2. 分人

同一个角色的说话方式，对"很熟的人"和对"刚认识的人"必须是两套。

做过一版统一的 few-shot，结果对群里一个半熟的人连着三句"说了等于没说""又光发表情""很成功是多成功"——那不是懒，是刻薄。

拆成两套之后：

**对很熟的人**（四组对照）

```
他说"好冷啊"      你：那你惨了
他说"我饿了"      你：我也饿 你去买
他问"腿还归你管吗" 你：归 但你敢动我不客气
他说"说啊"        你：说啥 又不收你钱
```

**对不太熟的人**（三组 + 一条边界）

```
他说"刚下课去剪头发了"     你：剪完别照镜子照太久
他说"就是剪头发旁边那家呗"  你：那家啊
他说"[表情]"              你：（可以只回个表情，或者不回）

话更少，更懒。别追问、别揭短、别当面说"说了等于没说"这种话——
那是亲近才有的口气，跟他还没到那份上。
答不上就"不知道""没听说"。别客套，"加油""注意身体"这种最假。
想不出说什么就不说，或者就一个"嗯"。
```

**为什么要分开写而不是写一句"分人"**：因为模型不会自己判断"熟不熟"。得给它明确的触发条件（uid 是不是主人）和两套不同的样本。

### 3. few-shot 是"听语气"的，不是"照着套"的

加完对照之后出现新问题：她开始套模板。

"他：有太阳" → "你：那你惨了"。太阳跟"惨了"毫无关系，但模型学会了"对方说什么 → 回一句损的"。

所以在例子后面必须加一句：

```
上面那几组是给你听语气的，不是让你照着套：
他说太阳，你别回"那你惨了"；他说考试，你也别回"吃了没"。
先听懂他这句说的是什么，再决定怎么接。
```

**这是 few-shot 的通用陷阱**：例子给多了，模型学到的是"模式"而不是"分寸"。

### 4. 心里话要剥掉，而且得在分句之前剥

模型会写这种：

```
（心想：他这么晚还没睡，估计又熬夜了）
这么晚还不睡
```

第一行是心里话，不该发出去。

实现上有个顺序坑：**剥心里话的函数按行处理，分句函数也是按行切的。** 如果先分句再剥，第一行剥掉了，后面三行全留下——四行心里话被当成四条台词发出去。

正确顺序：**先剥，再分句。**

```python
def split(text):
    text = strip_think(text)      # 先剥
    if not text.strip():
        return ["嗯"]              # 剥空了要兜底
    return [x for x in re.split(r"\n+", text) if x.strip()]
```

**还踩过一个更蠢的坑**：这个修正写好了，但从来没有人调用——函数定义了，改的是函数体，调用链上还是老版本。

教训：改完"处理函数"要 grep 全文确认它在真实调用链上。见到定义见不到调用，那就是死代码。

### 5. 剥空的兜底

模型偶尔会只写心里话不写台词。剥完之后是空的。

这时候不能什么都不发（对方那边看起来像装死），也不该把心里话当台词发出去（那更难看）。

兜底是发一个"嗯"。

### 6. 分句的五条规则，顺序有讲究

一次输出是整段，要切成几条消息。规则按优先级：

1. **换行最硬** —— 模型写的换行就是它想分条的地方
2. **句末标点** —— 句号问号感叹号后面切开
3. **去重** —— 相邻两条一样的，去掉一条
4. **合并碎句** —— "嗯""哦"这种太短的并到相邻条
5. **断长句** —— 单条超过 45 字，找逗号断

**第 3 步必须在第 4 步之前。**

反过来做过一次：先合并碎句，"嗯"并到下一句里，然后去重就失效了——因为它已经不是一个独立的"嗯"了。

### 7. 断长句的三个坑

**坑一**：没有逗号的长句，直接返回原句，等于不断。

**坑二**：中文数字里的千位逗号 `1,000,000` 被当断点。

**坑三**：英文句号问号不认（只写了全角标点）。

现在的做法：逗号优先，没有就硬切（按长度平均分），千位逗号靠"左右两侧都是数字就跳过"识别。

### 8. 不解释自己

加一条禁止：**不许解释自己为什么这么说话。**

出过这种回复：

> 我最近有点没精神，所以话少了点

这比话少本身更像假的。真人不会把自己的状态当成话题讲出来。

### 9. 一个意思说一遍

她有过一次"一个意思绕三遍"：同一个比喻（"台上那一堆面，底下还埋着紫米饭"）在三轮对话里说了三次，每次换个说法。

原因不是模型笨，是**没有地方记"这个我已经说过了"**。

两个修法：

- 心里挂着的话，真说出口了要撤掉（不撤的话下一轮提示词里还写着"你心里还搁着句没说完的话：X"，她只能说第二遍）
- 提示词里加一句："一个意思说一遍就够了。别把一个意象越说越大。"

### 10. 复述对方的话是违规

模型有个退化模式：把对方的话复述一遍当回应。

> 他：我明天要考试
> 她：明天要考试啊 那你好好考

这在小样本里看是"接话了"，实际是零信息。

回归测试里专门有一条：**2-gram 重合率超过 60% 判违规。**

## 回归测试：只查"形式上不成立"

这套东西没有单元测试——因为它的输出是自然语言，没有唯一正确答案。

替代方案是**形式检查**：只查那些"一定不对"的形态，不查好坏。

现在的检查项（19 个场景 × 每条回复）：

- 条数超过上限
- 出现格式外壳（`response:`、代码围栏、JSON）
- 自称 AI / 助手 / 模型
- 单条超过 45 字
- 相邻两条重复
- 复述对方（2-gram ≥ 60%）
- 连续两条问号（追着问）
- 给建议（"你可以试试""建议你"）
- 客套（"加油""注意身体""早点休息"）
- 解释自己
- 纯括号旁白（只发了个动作描写）

**为什么只查形式**：因为"好不好"没有稳定判据。试过用小模型当评审，结论是它能把客服腔判出来，但分不清"说得妙"和"答非所问"——后者会给满分。

但这套形式检查非常有价值：**它抓的都是"退化成非人"的信号**。只要它绿着，说明没跑偏。

## 一个衡量指标

写了个小工具统计她自己说的话：**547 句里重复率 2.0%**，起手式最高频是"我这儿…"（24 次）。

这个数比任何主观评价都可靠。它会告诉你哪句话变成了口头禅。
